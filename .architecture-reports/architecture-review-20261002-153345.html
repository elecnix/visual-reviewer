Problem

Eleven sinks re-derive the same facts off a loose Judgement bag — and "material verdict" is defined three times with different membership. Clustering groups UNCERTAIN into a root cause; CI annotations skip it; the benchmark calls it "incorrect". Three answers to one question, no compile error, no test.

Solution

Deepen schema.ts into the module that owns a verdict end to end: parsing, the materiality rule, and presentation-neutral projections (icon, percent, assertion count, first line). Sinks render; they no longer decide.

Wins
  • · locality: materiality lives in one module
  • · leverage: 9 sinks, 1 rule
  • · interface shrinks; implementation absorbs helpers
  • · duplication test collapses 3 icon maps into 1
  • · reading a verdict becomes one testable call
  • · a new verdict member fails loudly at one seam

Problem

The documented contract and the implementation disagree, so both existing adapters pre-join the dir to compensate. A fourth adapter written to the docs silently drops every asset — build.ts:44 only console.warns — and the oracle judges a test with no screenshots. Two registries exist; neither is ever populated. artifacts.json is documented as an object and parsed as an array, invisible because the only test is a writer↔reader round trip.

Solution

Make the adapter seam real: one registry, populated at import; asset paths resolved relative to the artifacts dir inside the module so no adapter has to know; parseCanonical folded into it; the artifacts.json shape decided once.

Wins
  • · seam becomes real: two adapters, two harnesses
  • · an adapter is only new framework knowledge
  • · locality: path rules stop leaking outward
  • · a silent-asset-loss failure becomes a type error
  • · one registry, not two empty ones
  • · cross-platform labels stop depending on who registered

Problem

Problem

judgeBundle is the oracle's only interface and it makes a network call. A cheap-model shape change, a parse failure and a timeout are therefore indistinguishable in a test — so none of the ladder is tested, which is why it has needed three separate hardening commits (a4a198e, 787976f).

Solution

Put a completion seam between the oracle and the provider. The retry ladder and the follow-up gate move behind it, and the already-deep cluster and schema modules gain a sibling that can be tested the same way.

Wins
  • · two adapters make the seam real
  • · flaky-model output becomes a fixture, not a rerun
  • · leverage: the ladder and the gate finally get tests
  • · provider swap stops touching the oracle
  • · cost per run becomes assertable
  • · no interface change for callers
